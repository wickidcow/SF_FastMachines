# FastMachines v1.0.5 — ItemsAdder and PredicateRecipeChoice safety

**New immutable release.** This version preserves the existing FastMachines item IDs,
recipes, machine inventories, power costs and stored data.

## Fixes

- Recognizes modern Paper/third-party cooking ingredients implemented as
  `PredicateRecipeChoiceImpl`, instead of failing the entire FastFurnace
  recipe registration with `Unknown RecipeChoice type`.
- Delegates ingredient matching to the **original Bukkit recipe predicate**.
  A custom ItemsAdder Raw Duck with a vanilla CHICKEN base material is **not**
  treated as equivalent to ordinary raw chicken.
- Isolates malformed individual registry recipes: one problematic addon
  ingredient should not prevent the remaining valid recipes from loading.
- Preserves exact ingredient amounts and alternative-group allocation;
  overlapping ingredient groups must not double-spend the same items.

## Compatibility and verification

The release build compiles and tests against Paper/Purpur 1.21.11, Paper 26.2,
and stable Paper 26.3. It builds one canonical Java 21 shaded plugin JAR,
validates its plugin.yml version and relocated dependencies, checks every
class file for Java 21 compatibility and publishes only from a fully green
master SHA with the exact same-run GitHub artifact digest.

**Live ItemsAdder Raw Duck / FastFurnace behavior has not been validated on
AlbionMC**. Test it on a backed-up staging server and report any unexpected
recipe matching. Passing source build and unit fixtures is not proof of every
third-party cooking integration or production inventory persistence.

## Install

1. Stop Paper/Purpur and back up the server and Slimefun/machine data.
2. Replace the previous FastMachines JAR with the single raw
   `SF_FastMachines1.0.5.jar` (do not leave a duplicate older JAR).
3. Start the server. Confirm FastFurnace loads its vanilla and ItemsAdder
   cooking recipes, including custom Raw Duck versus ordinary chicken.
4. Validate exact input/output counts for one craft and a full bulk batch,
   then restart and recheck the inventory and production logs.

No automatic migration, old data rewrite, or opt-in setting has been enabled.
The published v1.0.4 tag and assets remain unchanged.
